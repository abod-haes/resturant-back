# W09 — Web Push integration
B01 inventory: Expo device registry stores encrypted tokens, limits active devices to five, and scopes registration to employee and operational entitlements. Dispatcher expands call_outbox into push_deliveries, claims with leases, checks shift and entitlement, expires calls after 120 seconds, and polls Expo receipts. Existing outbox state is shared; a separate web worker must not race Expo for pending rows.
B02 proposed contract: GET /employee/web-push/config returns enabled and publicKey; POST /employee/web-push/subscriptions registers endpoint, keys p256dh/auth and expirationTime; DELETE /employee/web-push/subscriptions/:id revokes own subscription. Return metadata only. Use HTTPS endpoint validation, trusted provider allowlist, no redirects, bounded timeout, encrypted subscription, hashed endpoint uniqueness, employee ownership, limit and rate limiting. Bind subscription to authenticated session and revoke on logout; recheck eligibility at dispatch. Separate web delivery table with unique outbox/subscription, expand both channels in same transaction before changing outbox state; aggregate both channels, no Expo receipt polling for web. TTL 120 seconds, retry transient errors, deactivate 404/410, notification tag callId. Never claim delivery to device from provider acceptance. W09 frontend: explicit user gesture, service worker push/click, revoke on logout, iOS installed home screen support. No custom background sound guarantee. Implementation and tests pending.
