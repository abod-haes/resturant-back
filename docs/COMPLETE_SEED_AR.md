# Seed كامل للتجربة على قاعدة المطاعم الحالية

> لا يحذف أي جدول، حساب أو مطعم قديم. تم إلغاء سكربتي seed-demo وseed-staging-accounts واستبدالهما بـ db:seed:complete. إزالة السكربتات من Git **لا تحذف الصفوف التي أضافتها سابقاً**.

## البيانات

- مدير نظام واحد: `platform.admin`.
- مطعم الياسمين (`yasmin`) والورد (`ward`)؛ يعتمد على Slug المطعم الحالي، ويستخدم **معرّف قاعدة البيانات الحالي** بدلاً من فرض ID جديد.
- مالك: `demo.yasmin.owner` و`demo.ward.owner`.
- موظف غارسون وموظف أراكيل لكل مطعم: `demo.yasmin.waiter`، `demo.yasmin.hookah`، `demo.ward.waiter`، `demo.ward.hookah`.
- فرع رئيسي واحد لكل مطعم: `yasmin-main` و`ward-main`. الفروع الأخرى الموجودة تُحفظ دون تغيير.
- طابق أرضي، منطقة داخلية، 5 طاولات لكل فرع رئيسي مع QR credentials حقيقية مشفرة وفق منطق الباك.
- 4 أقسام × 4 منتجات = 16 منتجاً لكل فرع، بإجمالي 32 منتجاً (USD للمعاينة).
- باقة تجريبية تسمح بالمنيو واستدعاءات الغارسون والأراكيل؛ اشتراك فعّال لمدة سنة **فقط إذا لم يكن هناك اشتراك فعال مسبقاً**.
- إعدادات استدعاءات للمطعم والفرع من دون الكتابة فوق إعدادات موجودة.

**السكربت لا ينشئ دواماً نشطاً لموظف تلقائياً**: كل موظف يبدأ دوامه من تطبيق الموظفين لتجربة التوجيه الحقيقي. الصور لا تُضاف، لأن Media Storage يحتاج رفع ملفات حقيقية.

## تشغيل Dokploy على نفس Backend الحالي

استخدم `production → restaurant-backend → Terminal → /bin/sh`، وليس Environment جديداً. اعمل Redeploy لأحدث `main` أولاً. ثم:

```sh
cd /app
npm run db:migrate:check
export APP_ENV=production
export SEED_FULL_CONFIRM=I_UNDERSTAND_THIS_WRITES_TO_PRODUCTION
# First: validate the full operation without saving any change
npm run db:seed:complete -- --dry-run
# Only after checking the dry-run output:
npm run db:seed:complete
unset SEED_FULL_CONFIRM
```

يجب أن يكون `DATABASE_URL` و`QR_TOKEN_ENCRYPTION_KEY` موجودين أصلاً في **Backend Environment**. لا تعرضهما ولا تنسخهما للكاستمر.

### إعادة تعيين كلمات مرور حسابات Seed الموجودة سابقاً

السكربت يولّد كلمة مرور عشوائية قوية لكل حساب جديد ويطبعها **مرة واحدة داخل Terminal بعد نجاح COMMIT**. الحسابات القديمة لا تتغيّر، لذلك إذا لا تعرف كلمات مرور حسابات الاختبار الموجودة، استخدم هذا الخيار الصريح **مرة واحدة**:

```sh
cd /app
export APP_ENV=production
export SEED_FULL_CONFIRM=I_UNDERSTAND_THIS_WRITES_TO_PRODUCTION
export SEED_RESET_DEMO_PASSWORDS_CONFIRM=RESET_ONLY_NAMED_DEMO_ACCOUNTS
npm run db:seed:complete -- --reset-demo-passwords
unset SEED_FULL_CONFIRM SEED_RESET_DEMO_PASSWORDS_CONFIRM
```

هذا يغيّر كلمات المرور فقط للحسابات المسمّاة في السكربت، ويُبطل جلسات تسجيل الدخول السابقة لهذه الحسابات، ويضع `must_change_password=true`. لا يشمل أي حسابات أخرى. احفظ كلمات المرور الناتجة بمدير كلمات مرور؛ لا تنسخها إلى GitHub أو المحادثة.

يمكن تحديد كلمات مرور اختيارية مختلفة (12–128 حرفاً) عبر متغيرات مؤقتة مثل `SEED_PASSWORD_PLATFORM_ADMIN`، لكن الأفضل استخدام التوليد الآمن الافتراضي.

## الحماية وإعادة التشغيل

- السكربت Transaction واحدة مع Advisory Lock؛ إذا فشل أي جزء يتم Rollback.
- يبحث عن المطعم بــ slug والفرع بــ slug، ويرفض الربط مع Tenant مختلف.
- الحسابات الموجودة تُربط بالمالك/الفرع الصحيح، ولا يعاد إنشاؤها.
- المنتجات والأقسام والطوابق والطاولات الموجودة لا تتكرر؛ لا يكتب فوق تغييرات الإدارة.
- أي QR موجود يُحفظ بنفس التوكن؛ QR ملغى لا يُعاد تفعيله خلسة.
- لا يحذف بيانات Production، ولا يستخدم `TRUNCATE` أو `DROP`.
- إذا الاشتراك الحالي غير صالح، يوقف التنفيذ ويطلب إصلاح الاشتراك من Admin Dashboard بدلاً من استبداله.
- لا تشغل السكربت على قاعدة خاطئة أو بدون نسخة احتياطية قبل التغييرات على Production.

## اختبار المنيو والـ QR الحقيقي

بعد نجاح العملية، افتح المنيو العام `/m/yasmin-main` على Customer. هذا يعرض المنتجات بدون زر استدعاء.

للاستدعاءات: من لوحة مالك الياسمين، افتح قائمة الطاولات، واختر QR الطاولة الأولى واعرض/اطبع رابط QR الحقيقي. افتح الرابط `/t/<token>` على Customer (النسخة المحلية أو المنشورة). هذه القيمة **Token خاص بالطاولة** وليست `restaurantId` وليست `QR_TOKEN_ENCRYPTION_KEY`. يبدأ الموظفون دواماتهم من التطبيق حتى تصلهم الاستدعاءات.

لتشخيص وجود المنتجات والطاولات بعد التنفيذ، افحص `summary` المطبوعة في Terminal، ثم تأكد من البيانات من لوحات الإدارة والمنيو.


## الفحص قبل الكتابة

استخدم `npm run db:seed:complete -- --dry-run` أولاً. هذا ينفّذ جميع عمليات الفحص والإدخال داخل Transaction ثم يرجعها بالكامل، ولا يطبع كلمات المرور التجريبية التي تم توليدها خلال الفحص. الملخص يعرض عدد السجلات التي **كانت ستُضاف**، وليس السجلات الموجودة بالفعل. تأكد من نجاح هذا الفحص قبل التشغيل الحقيقي، وتحقق من أن DATABASE_URL يشير لنفس قاعدة السيرفر المقصودة.

**تنبيه مهم:** سبق أن ظهر مفتاح تشفير QR في المحادثة، لذلك يجب التخطيط لتدويره بأمان لاحقاً بعد حصر رموز الطاولات المشفرة بالفعل، دون تعطيل QR الحالي بمجرد تغيير المفتاح.
